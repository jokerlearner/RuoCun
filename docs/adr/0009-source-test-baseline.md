# ADR-0009：以DAO已有测试为默认验收基线

Status: Accepted
所选功能、V1成套live成绩和V2量化性能承诺按[ADR-0010](0010-selected-scope-and-lean-workflow.md)修订；来源测试语义迁移与必要工程确认原则保持。
日期：2026-11-10
决定来源：用户明确“这个项目做的时候，测试只用通过dao给的那些测试就行了，不用给特别多的测试”。

## 决定

后续产品自动验收以冻结DAO已有测试、fixture及脚本的语义迁移与通过为基线；优先复用输入、独立预期和来源断言。TypeScript绑定按Python公开接口做必要改写，来源行为与已有明确差异决定分别记录。

不主动扩建额外的故障注入、竞态/压力/排列边界、组合真实任务或第二套独立测试框架，也不把这些额外覆盖不断加入每票完成门槛。项目TDD适配为：来源已有失败断言→最小实现→原断言通过；已有缺陷的回修复用已捕获的最小复现。通用任务票与参考技能中要求额外测试的描述以本决定为准，原参考文件保留。

已有测试和失败证据保留，正在运行的检查安全收尾。已确认会错误写入、错误恢复或破坏来源行为的缺陷仍须最小修复并用已有复现确认；纯静态疑点或额外探索假设不再自动升级为无限扩测的阻断。记录未覆盖范围，不能删除失败、跳过已确认来源断言或回填通过来缩短时间。

## 复核与工程检查

独立代码审查、逐票证据和集成继续；审查者核对来源与运行已有测试，不再每票另写大量独立脚本。纯文档合并以产品字节核对为主；修复后先重跑受影响的来源用例/已有复现，有新失败或实际关切才扩大回归。

编译/静态检查及必要的安装、启动可运行确认沿用既有入口。新Python/Windows适配没有来源测试可直接运行时，只做验证可交付所必需的最小确认，明确它不属于DAO来源测试通过。当前已批准依赖工具适配的有限既有用例可以收口，不继续扩大工程测试矩阵。

最终人工体验、已确认功能差异和性能阈值仍分别记录；尚未执行的测量、真实模型或平台检查保持未验，不因来源测试通过就声称它们已经通过。真实模型沿来源已有资产和明确预算执行，本轮不新增组合任务作为默认自动门禁。

## 影响

本决定调整测试与复核投入，功能目标依ADR-0008及既有规格保持。原验收矩阵用于追踪能力、来源对应和真实结果；不再要求在每个案例族构造超出来源资产的所有失败/恢复排列。后续接续和派发均先读本决定。

07当前已亲验的关联错误按DAO event(snapshot)同源契约最小修复；已有检查完成后收口，不继续扩展新竞态假设。状态、实际结果和本次启动授权仍以[实施进度](../../.scratch/ruocun/implementation.md)为准。
