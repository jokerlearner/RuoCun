# ADR-0015 — 按里程碑验收并复用定向证据

Status: Accepted
日期：2026-11-11

用户确认采用推荐加速节奏，并愿意协助真实 Windows Terminal 技术操作。随后确认采用A扩大普通批次、B复用工作会话并增量交接、C在里程碑汇总大型文档，内部模块继续按现有DAO对应迁移。本决定更新ADR-0010的普通批次、交接、文档更新、复跑和构包时点。

## 实施与审查

普通同领域任务按5–8票组织管理批次，按真实依赖分段实施。开发者运行直接受影响的DAO来源测试，修复缺陷沿已有复现做定向红绿。主协调复用绑定候选提交、命令、环境和结果的回执。高风险接缝按下段独立复核后供下游消费。

独立审查普通改动时审代码、来源契约和已有回执。发现具体疑点时运行能区分该疑点的用例。权限、持久化、恢复、进程取消与共享执行身份等高风险接缝，仍由独审定向复跑后集成，后继再消费。

批内保留逐票提交、硬依赖与完成证据。独审通过前的候选维持在途状态。主协调在计划中明确下一次可交付里程碑，集中运行一次已迁移全量与工程入口。中间提交根据实际改动运行相关来源测试及静态检查。

## 上下文和文档

同领域接续复用负责人、工作会话、worktree和私有环境。任务卡只列票号、相对上次保存点的变化、必要来源和接口、文件归属及验收入口。接手者先核对增量，再按缺口读取权威文件。结果交接记录提交、改动、实际回执和待处理问题。

日常更新逐票状态与一份批次记录。大型模块对应表和验收矩阵在里程碑统一汇总，汇总前的最新实施进展读取任务票和批次记录。涉及关键行为的决定随实施及时记录，公共表在交付前与逐票证据对齐。原始来源索引及已有回执继续可追溯。

Python模块按现有对应表迁移，保留职责、来源位置和关键失败兜底的对应关系。批次扩大通过复用上下文、验证和记录减少开销。

## 构包和复验

准备交付，或验证依赖、包元数据、入口、资源、平台库和安装行为时构包。普通模块实现阶段使用源码与定向回执。独审和集成复用同一套固定产物及其安装证据。

行为改动后的修复运行受影响路径，按里程碑收敛全量。纯换行、文档或资源修正按对应影响复核。纯换行先逐字节证明仅统一 LF/CRLF，绑定语义相同的旧功能回执，再对新包核源码、成员字节、资源与受影响的内部角色启动。资源修正核资源加载及消费路径。

每份沿用的回执记录原产品和产物指纹、新产品指纹、差异证明及复用范围。原失败继续保留。新包的功能全量状态写明沿用哪次结果，区分本次实际运行项。

## 本轮应用

N24-r1 的168个包成员中，仅 conversation.py 的350处换行在工作树、sdist、两种wheel和实际安装中为CRLF，而冻结Git归档为LF。两名独立检查者确认其余字节相等。严格字节绑定仍为失败，证据见[逐成员报告](../../.scratch/ruocun-next24h/evidence/n24-package-bytes/README.md)。

按仓库已有 eol=lf 修正工作树后生成r2，复核严格字节绑定和同包内部角色启动。r1全量实际为1445 passed、4 failed、3 deselected。4项失败均在同一测试夹具把源码专用loader定位到已安装环境不存在的tests目录，runner退出2。夹具修正为源码模式使用显式loader，安装模式使用实际默认模块入口，原4项断言定向复验。r1通过项在上述差异证明范围内复用，失败项保持原始回执并引用修复后结果。

## 人工参与与代价

普通跨模块回归可能在批次末尾才发现，返工可能涉及一批提交。中途公共汇总表可能滞后于任务票。四槽、文件归属、小提交及批次记录用于定位影响。token收益按减少重复读取、交接和文档改写估计，实际消耗尚未计量。

用户可协助真实终端按键、粘贴和缩放，代理保存请求、会话与退出证据。具体技术项据反馈及回执判定，整体体验仍归77。范围、关键行为、新费用和系统安装等决定继续集中提交用户。既定范围内的实现由代理连续推进。
