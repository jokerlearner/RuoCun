# ADR-0007：允许管理员预装的Windows隔离强制层候选

Status: Superseded by [ADR-0008](0008-source-first-sandbox-parity.md)
日期：2026-11-10
决定来源：用户在解释文件/网络OS隔离与安装影响后选择“愿意接受额外组件，先在可回滚测试环境验证”。

## 决定

用户后续明确要求模仿DAO已有沙箱能力，已由ADR-0008停止额外Windows原生组件评估。以下保留该次讨论和授权的历史，不作为当前安装/研究任务。

完整Windows沙箱允许新增一次管理员预装签名driver/service及WFP组件的产品前提，Python仍负责业务和编排，主程序及日常运行的普通用户路径仍须实测。本决定修订规格R-15中“普通用户安装”的整体前提：主程序与原生隔离强制层分开验证，后者可以要求管理员预装。候选名称、固定版本、签名/hash、许可、安装/升级/卸载和故障拒绝尚未决定。

先在可回滚Windows VM或专用测试环境评估候选。当前没有授权在日常宿主安装驱动/服务、修改防火墙或启用系统功能，也没有授权自动重启、购买许可证或发送上游消息。环境需要这些步骤时先提交具体可审查方案；可以继续不依赖该条件的产品工作。

## 验证与门禁

以[D22冲刺诊断](../../.scratch/ruocun-discovery/research/22-sprint-diagnosis.md)路线二为候选方向，不把Sandboxie或任何工具直接当作通过后端。先验证允许根写成功，原同用户owner、未改outside ACL下WRITE_DAC单独/混合、WRITE_OWNER和真实无害ACE改动均被拒绝，host读回不变；任一成功或需放宽限制即停止。默认copy-on-write外写成功不能替代拒绝外写。

仅此前置通过后再验证工具链、子代、重解析、已有句柄、网络及禁网、取消/后台/恢复和组件故障时拒绝。候选通过仍只解锁产品后端实施，60/61/78及最终安装产物和用户体验须各自验收。D22当前A仍失败、B/C未运行，既有停止规则及安全目标保持；不得借新安装前提把旧失败改为通过。

## 影响

- D12纳入原生依赖、管理员预装与普通用户日常运行的分离契约及许可核查。
- 最终隔离目标、功能和稳定性不减少，性能仍按ADR-0006测量。
- 没有可用测试环境或候选未通过时，保留安全/发布阻塞；继续已解锁的其它迁移任务。
- 启动时间、实际环境和调度状态统一见[实施进度](../../.scratch/ruocun/implementation.md)。
