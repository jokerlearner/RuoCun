# ADR-0013：阶段A之后约20小时的连续开发

Status: Accepted
日期：2026-11-11

用户要求完成当前重构后继续开发，先讨论并保存后续约20小时安排，减少频繁确认。本轮选择Q1 A“动态Skills → 记忆”，并接受Q2失败处理规则。本决定授权[连续计划](../../.scratch/ruocun-next20h/plan.md)内的实施、验证、本地提交和独立集成；阶段A继续，不等待首版人工体验。20小时是规划检查点，质量优先，未通过继续修复；不承诺届时全部功能完成。

## 顺序与范围

阶段A自动技术出口通过后，核对并补齐08/34实际前置缺口；随后09权限与11调度并行，10工具日志/编辑和19搜索补齐，满足10+11后做12批处理，满足各自前置后并行35动态Skills与36安装，最后30→31→32记忆CRUD、注入和蒸馏维护。32优先级最低；20小时结束时报告可信保存点、剩余工作及更新估算。

MCP、后台任务/恢复、多代理、插件及完整TUI不加入本轮主线；原完整迁移规格保留。前置票必须真实满足，不能将MVP或阶段A局部覆盖当作原票resolved；未满足时先补前置，后继保持阻塞。原始任务图不改边来抢跑。

## 连续执行与提问边界

普通实现选择依据冻结DAO源码/调用方/测试自主决定。当前功能若遇到DAO失败兜底会丢弃已保存的信息，或重放结果不明的写入/执行操作，保留现场并停止受影响操作，登记具体来源分支、差异、恢复办法和受影响案例；其它独立工作继续。此项是用户预先接受的有限差异类别，不授权任意改变DAO正常行为。摘要失败仍按ADR-0012。

新增费用、系统安装、扩大功能范围或其它关键行为变化集中提交具体方案供用户选择。常规依赖补齐、排期调整、修复、审查和验收不逐项请求启动确认。计划内队列可连续推进，20小时到点保存并汇报，未完成项沿已批准范围继续；计划外批次另议。真实模型调用保持未授权，开发使用合成服务。

## 工程约束

沿ADR-0009/0010：冻结来源测试优先、必要Python/Windows工程确认、普通小批复用人员与私有环境、逐票证据、关键接缝先独审集成、四槽上限。唯一写入者维护共享入口/存储契约。人工体验与真实Windows Terminal继续单列pending；已有范围缩减、来源记录和许可保持。
