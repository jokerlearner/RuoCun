# ADR-0010：按用户选择收缩交付范围并减少执行冗余

Status: Accepted
日期：2026-11-10
决定来源：用户先确认Q1普通批末审查、Q2执行减负全部采用，随后明确“按表缩减：R1，R3，W3、W5，W6，D2,D3,V1,V2”。本决定覆盖ADR-0001/0005/0006/0008/0009及既有规格中与下表冲突的部分；其余决定保持。

本轮只落实工程约定、规格和计划，产品仍按[实施进度](../../.scratch/ruocun/implementation.md)保持停止。范围选择不是恢复开发、付费模型或系统实验授权。

## Q1：普通小批连续实现与独立审查

主协调在派发时区分普通任务与关键接缝。普通同领域2–3票可在同一负责人和worktree内连续实现，每票保留来源断言、最小提交及未完成项；批内前件须已有可调用代码、相关来源测试通过及明确接口，才继续依赖它的后件。主协调记录批内许可、前件候选SHA和文件归属。

普通小批完成后统一独立审查、复跑受影响的来源测试并集成。批内候选不对外解锁，票不提前resolved；跨负责人/跨批消费仍等待前件独立复核并集成。失败回修到受影响票，不把批末通过推定为所有票自动完成。

存储、权限、取消、恢复及共享运行契约等关键接缝仍先独立复核、集成再供下游使用。08主循环/工具journal、09权限、11取消等不能仅因批次名相同就归为普通。四槽上限、唯一文件写入者和独立审查身份继续保留。

## Q2：减少准备、验证和记录重复

1. 既有规格内的普通迁移按冻结DAO直接实施，优先复用原资源；只有实际范围或共享契约变化才增加设计/ADR。不给假设中的未来需求增加通用层。
2. 同领域跨批可复用负责人、分支/worktree与私有venv。每批记录实际基线、依赖锁和干净状态，合并接续并保留已有材料；可写环境不跨并行代理共享，HOME/配置/会话状态仍按批隔离。
3. 开发阶段运行受影响的DAO测试与定向静态检查；共享模块变化覆盖相关调用方，集成检查点及最终交付候选运行所选范围的已迁移全量。已确认缺陷复用原复现，不再堆额外矩阵。
4. 普通固定候选构建一套不可变产物，独立审查先绑定源码提交、产物内容/hash与实际安装版本再复用。源码或依赖变化使旧产物失效；依赖、元数据、入口、资源或平台库变化，以及最终交付候选，重新构建并作必要安装确认。
5. 一份批次记录列来源/差异、逐票修改范围、实际命令结果和未验项；逐票引用相同回执，公共表只更新相关行。原始失败与日志保留，不重复叙述历史。
6. 恢复后优先08解除主链阻塞，再依真实前置安排09与11等并行；28/58等支线填可用名额。审查积压时先审查修复，不无限追加实现。
7. Q2原建议的“有限性能检查集中在有效时点”按用户后选V2收口：不恢复量化比较或正式采样门禁，只据实际变化做必要观察与已证实问题复验。
