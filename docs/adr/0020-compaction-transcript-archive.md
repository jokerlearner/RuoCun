# ADR-0020 — 压缩策略与原文归档

Status: Accepted
日期：2026-11-13

用户选择核心压缩加完整原文归档的 B 方案，调用 to-spec 形成规格后，明确要求“根据 spec 方案完成计划”，并指定 TDD。本决定确认该实施范围及已发布计划的技术基线，不表示产品已通过验收。

## 决定

- 参考 DeepSeek Harness 固定提交 `e8f7b93a344964de3dca1ace9e72b6e4d6de87cb` 的预算、确定性工具文本裁剪、完整工具组切点、近期尾部、单份摘要重整与缩小检查；保留归属声明。
- 沿现有 SQLite/StorageWorker/Conversation 权威保存每执行范围的原文身份、分段及投影来源。原文批次、派生引用、新检查点/子执行快照及幂等回执同一事务确认。
- 复用 SQL 表与 `user_version=1`，使用独立归档格式和 `storage_version=3` 语义门禁。旧会话通过停止进程、备份与显式离线升级启用；不做启动静默转换，旧程序拒写新语义会话。
- 默认策略参考80%压力、16%近期材料；余量按模型适配，只有未显式配置的输出上限才随窗口调整。计量与真实请求一致，不冒充精确tokenizer。
- ADR-0012 的摘要失败/取消/保存未确认保留停止继续有效；先在候选副本裁剪与摘要，全部确认后才交换模型投影。不重放未知副作用。
- 原文按现有脱敏后的消息结构保存；内联图保留一次、外部附件登记引用，查询和导出受会话/执行范围限制。
- 清空和回退只改变当前投影并记录历史边界；分支仅复制当前投影可达的原文来源闭包，不继承父副作用权限。

## 2026-11-13 后续决定：摘要原始前缀复用

用户在对比缓存机制后明确选择进一步保留原始连续历史（该次讨论的 B 选项），并授权真实 API 测试；随后确认先验证现用硅基流动 DeepSeek-V4.1-Flash 渠道。增量范围和验收见[本次规格](../../.scratch/summary-prefix-20261113/spec.md)。

- 需要摘要时使用原始连续旧前缀，保留图片、Hook、Todo 和消息顺序。工具结果裁剪仍可避免不必要的摘要，但不能暗中改写已经选择的摘要输入；原始前缀放不下时停止并保留原投影。
- 默认同模型摘要继承本次有效请求的连接、工具定义/顺序与思考设置，末尾追加摘要指令；清除主轮强制工具选择与冲突输出 cap。显式异模型摘要继续尊重配置，不声称复用主模型 KV。
- 摘要不接入工具执行循环，工具调用回包拒绝提交；不通过强制 `tool_choice=none` 改变服务端工具模式。取消、失败、空/截断、未缩小和提交未确认的停止契约继续有效。
- 摘要来源如实包含完整输入，重叠原文按身份去重并按 raw_seq 回查。目标模型预览摘要仍读取当前旧 system 原文，最终投影另行发布新 system，避免把未提交新提示登记成旧来源。
- 原生 DeepSeek 官方 Chat 且带工具时按当前协议重放已有历史 reasoning；其它路由维持既有行为。真实验证的当前渠道仍为硅基流动，不把其结果冒充 DeepSeek 官方端点测试。
- 本轮高命中以预先固定的受控长历史、三次首摘要真实 hit/prompt 至少90%及最终 wire 连续消息前缀等值为验收；缓存服务端是 best effort，不承诺任意负载、重启/淘汰后的永久高命中。冷启动、失败、预热与输出费用全部记录。
