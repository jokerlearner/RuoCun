# ADR-0003：MCP结果不明时停止自动重放

Status: Accepted
日期：2026-11-05
决定来源：用户对已实测兼容差异明确回复“结果不明时停止自动重放（推荐）”。

## 背景与证据

[D15扩展实验](../../.scratch/ruocun-discovery/experiments/extensions/README.md)在受控服务先写副作用、再断线且不回结果的场景，实测冻结DAO manager自动重连重试使effect计数为2；候选Python SDK首次调用失败后计数为1。
这证明远端结果不明时重试可能再次执行，不代表原版承诺过exactly-once，也不把候选SDK默认行为自动当产品决定。

## 决定

- MCP工具调用可能已经发送并执行、但结果不明时，RuoCun停止透明自动重放，向用户呈现未决状态。
- 未决结果进入持久化与恢复流程，不能只记录普通失败后让模型换一个工具调用ID继续重做相同副作用。
- 连接、握手和能力发现仍可重连；重新连接不等于重新执行原工具请求。
- 确定未发送/未执行或收到明确结果的错误按其真实状态处理；证据不足保持未知。
- 再次执行须有明确用户恢复决定，不能仅凭模型建议、工具描述或readOnlyHint宣称安全。
- 保持MCP外部配置和工具schema兼容；这项执行语义差异纳入规格、验收矩阵及发行说明。

## 后果与验收

断线副作用计数器案例预期：来源可观察到2次，RuoCun在未明确授权重执行前保持1次并记录未决，重启后仍不重放。
工具journal、错误分类、恢复操作和UI需共同实现；协议实验不代表产品功能已经完成。
协议resumption、幂等服务端结果恢复等能力未经验证，不据此承诺支持或绕过本决定。
