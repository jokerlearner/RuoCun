# 69 首次启动引导候选

按已批准的批次和冻结 DAO 实现语言、服务商、密钥、目录信任四步。首次欢迎沿用同一个 InputBroker，隐藏原欢迎页脚。语言选择立即更新当前界面，服务商顺序为 DeepSeek、火山引擎、千帆、智谱。其默认端点和模型沿用已有配置目录。引导模块注入验证和持久化，普通入口由主协调接线。

密钥面板只显示掩码，粘贴去空白。空回车取消，失败按来源错误类型提示并保留原值可改，验证及保存期间继续由同一面板接收输入。追加回车、按键和粘贴不提交主草稿，成功只保存一次。信任面板显示实际目录和项目配置范围，只有明确输入 y/Y 才允许，其他常规按键含 Enter 和 Esc 默认拒绝。Ctrl+C、Ctrl+D 或 owner 退出取消引导。来源顺序为验证成功、保存账户、选择信任、保存语言、明确同意时才写信任。异常保留已确认的写入现场，停止当前引导并显示不含底层异常或密钥的提示，保留来源的失败退出行为。

`runOnboarding` 接受同一个已启动的 InputBroker 和注入端口，返回 `{resolved, lang, trusted}` 或 `None`。`ask_secret_validated` 与 `ask_trust` 复用原模态锁与唯一读入链。上层拥有 broker 生命周期、账户和语言文件、信任写入以及后续普通会话。首次运行后的持久状态、独审与实际 Windows Terminal 结果由主协调另记。

`source.json` 绑定冻结来源及来源测试。`flow-red` 的真实失败为缺引导入口，`owner-red` 为真实输入 broker 缺新面板方法。最终 `targeted` 通过 7 项，包括 5 项来源流程、实际 InputBroker 的密钥重复输入/掩码/信任单键接缝以及 1 项原审批输入回归。Ruff 和 11 源 mypy 通过。回执使用 tools/run 的明确白名单及合成 HOME、配置和临时目录，输入均为合成值，秘密扫描为 false。
