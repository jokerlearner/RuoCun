# DeepSeek Harness 风格压缩与完整原文归档规格

日期：2026-11-13（Asia/Shanghai）
主任务：[02 — 实施 B 方案](issues/02-compaction-and-archive.md)

## Problem Statement

用户希望 RuoCun 能连续处理长任务：压缩后仍记得刚出现的报错和最新要求，早期历史变短，但用户与模型需要时还能查回实际保存过的原文。

当前上下文压缩将历史整体替换为文字摘要，近期原文也会消失；再次压缩保留旧摘要并追加新内容，摘要可能持续增长。压力判断主要依赖上次 API 用量，新输入和工具输出增加后的请求不一定提前得到保护。当前持久会话主要恢复最新检查点，不能据此承诺压缩前全部原文可恢复。

用户已明确选择 B：核心压缩机制＋完整原文归档与回查。希望参考 DeepSeek Harness 的公开实现，同时保持 Python、现有职责分工与低维护复杂度。

## Solution

压力达到阈值后，先在候选副本中裁剪可安全处理的大工具正文，重新测量；仍有压力时，把工具配对完整的旧段连同旧摘要重新整合，保留预算内的近期原文。候选必须确实变小，摘要、工具裁剪前原文、来源引用和新检查点一起持久化确认后，才替换模型上下文。

归档与当前模型投影分开：模型平时只看到必要摘要和近期材料；用户可列出、分段读取和导出归档，模型可通过只读工具按引用取回。归档不会自动重放任何工具或用户输入。

本规格中的“原文”是现有程序已接纳、已脱敏的完整消息及必要元数据，包含调用与结果、推理/协议字段以及图片附件引用。它不指原始 HTTP 数据包或凭据，也不承诺修复旧版本已经遗失的历史。

## User Stories

1. **US01**：作为长任务用户，我希望上下文接近容量时自动压缩，以便不中断当前目标。
2. **US02**：作为用户，我希望手动压缩使用同一套规则，以便行为可预测。
3. **US03**：作为用户，我希望最近的请求和报错保留原文，以便压缩后仍能准确接续。
4. **US04**：作为工具使用者，我希望调用及全部对应结果完整保留或一起归档，以便模型不会收到孤立工具结果。
5. **US05**：作为用户，我希望过大的普通工具正文先做无需模型的裁剪，以便节省摘要成本。
6. **US06**：作为用户，我希望工具正文被裁剪后仍能查回完整已保存结果，以便核实中间细节。
7. **US07**：作为用户，我希望旧摘要在后续压缩时重新整理，以便摘要不会无限追加。
8. **US08**：作为用户，我希望系统指令、项目规则和本次启动 Hook 保持有效，以便压缩不改变工作约束。
9. **US09**：作为用户，我希望当前任务清单单独保留，以便已完成项和未完成项不会因摘要失真。
10. **US10**：作为用户，我希望触发压缩时考虑输出预留，以便模型有空间完成回答。
11. **US11**：作为用户，我希望新增的大段输入和工具定义也参与预算，以便不只依赖上一轮统计。
12. **US12**：作为多模型用户，我希望切换模型后按目标窗口重新检查，以便小窗口模型不会直接收到过大的历史。
13. **US13**：作为用户，我希望摘要失败或为空时保留原上下文并停止本轮，以便原有信息不被丢弃。
14. **US14**：作为用户，我希望取消能阻止继续请求和工具执行，以便压缩不会越过停止操作。
15. **US15**：作为用户，我希望提交结果不明时保留现场，以便不会重复归档或重复执行。
16. **US16**：作为用户，我希望归档原文与新摘要同时保存成功，以便不会出现有摘要却没有原文的状态。
17. **US17**：作为长期会话用户，我希望多次压缩仍可按来源展开历史，以便同一片段不重复、不串序。
18. **US18**：作为用户，我希望关闭进程后重开仍能读取归档，以便归档不是内存缓存。
19. **US19**：作为用户，我希望列出归档的时间、范围、原因和引用，以便判断应该读哪段。
20. **US20**：作为用户，我希望按范围分页读取原文，以便一次读取不会再次撑满上下文。
21. **US21**：作为模型调用者，我希望模型能用只读工具按引用查回原文，以便摘要不足时继续查证。
22. **US22**：作为用户，我希望默认导出包含可恢复的完整历史，以便会话记录便于复盘。
23. **US23**：作为用户，我希望也能只导出当前模型上下文，以便检查模型实际看到了什么。
24. **US24**：作为用户，我希望真实重复说过的消息都保留，以便系统不会按文本相同错误去重。
25. **US25**：作为已有会话用户，我希望有明确的备份和离线升级入口，以便保留现有数据后启用新能力。
26. **US26**：作为用户，我希望升级失败后旧数据仍可使用，以便失败不会把会话变成空记录。
27. **US27**：作为用户，我希望旧程序拒绝写入新归档格式会话，以便历史引用不会被旧实现破坏。
28. **US28**：作为用户，我希望旧摘要缺少原文时明确标注，以便不会把生成内容当成真实原文。
29. **US29**：作为后台任务用户，我希望等待期间压缩不改变等待身份，以便任务结果能正常返回。
30. **US30**：作为用户，我希望迟到结果和未投递事件最多确认一次，以便压缩或重启不重复消费。
31. **US31**：作为图片使用者，我希望归档保留已有附件引用和投递状态，以便不会重复上传或伪造已恢复图片。
32. **US32**：作为子代理使用者，我希望各执行范围独立归档，以便子代理不会读到未授权的父会话历史。
33. **US33**：作为会话分支用户，我希望分支拥有闭合的归档来源，以便源会话被清理后分支仍可读取自己的历史。
34. **US34**：作为用户，我希望清空或回退只改变当前工作投影，同时保留并标记相应历史，以便能复盘操作边界。
35. **US35**：作为用户，我希望归档与所属会话共同管理和清理，以便不出现悬空引用或无限遗留的临时副本。
36. **US36**：作为用户，我希望历史读取沿用当前权限和脱敏边界，以便普通子代理或外来引用不能越权读取。
37. **US37**：作为维护者，我希望自动、手动和超限恢复共用策略，以便避免三套压缩行为逐渐分叉。
38. **US38**：作为用户，我希望能区分未缩小、没有安全区间和真正成功，以便不会误以为反复压缩已经解除压力。
39. **US39**：作为维护者，我希望固定上游版本、保留许可并有定向测试依据，以便后续能解释每项借鉴与适配。
40. **US40**：作为用户，我希望新安装包在仓库外也能完成压缩、重开和回查，以便源码测试通过后产品仍可使用。

## Implementation Decisions

以下决定区分已确认约束与本次技术提案。已确认约束包括 B 范围、Python、失败保留停止、未知结果不重放、现有权限和独立持久化权威。具体预算默认、归档记录格式和命令参数为本次计划给出的实施基线。

1. **D01 — 统一处理链。** 请求前预算、自动压缩、手动压缩、目标模型检查和超限恢复使用共同的候选生成和提交接口。普通网络重试不替代上下文恢复预算。
2. **D02 — 同一口径计量。** 计入最终请求的系统、工具、当前消息、图片估算和有效输出限制。API 用量用于校准和报告；估算不得冒充精确 tokenizer。
3. **D03 — 明确容量策略。** 默认压力比例参考 80%，近期保留比例参考扣除输出预留后预算的 16%。额外余量按窗口适配；对小窗口和显式输出设置作合法性检查。估计的输出预留必须与实际发送的限制一致，用户显式设置不得静默改小。
4. **D04 — 两阶段减量。** 在深拷贝上先裁剪普通工具正文，再决定是否摘要。压力解除后跳过摘要模型；若仍需摘要，则整次候选成功后才提交，保持失败前投影不变。
5. **D05 — 不可切开工具组。** 选区以调用 ID 及其结果建立完整配对，按 token 预算从尾部保留近期原文；系统锚点、必要 Hook、当前 Todo 和恢复权威数据受保护。不能安全缩小时明确无进展。
6. **D06 — 单份摘要。** 旧摘要与选中的旧段共同整理成新摘要，替换永久追加策略；旧 Todo 不叠加，来源引用由程序生成而不由摘要模型猜测。
7. **D07 — 硬性有效性检查。** 空白、失败、只有推理、输出截断、取消和未严格缩小的摘要不得替换原文。摘要请求本身超过目标模型容量时停止并提示，不通过丢弃资料伪造成功。
8. **D08 — 快照与并发。** 候选绑定准备时的模型投影和范围身份，在提交锁内复核。排队输入可以独立增加账本版本；不能仅靠数据库 revision 判断模型投影是否发生变化。
9. **D09 — 单数据库权威。** 归档使用现有 SQLite 的独立分段记录，避免外部归档文件与数据库形成新的双提交权威。普通保存按执行范围增量归档已接纳原文，压缩仅新增派生记录并切换投影。归档批次、新引用清单、新检查点或子执行快照及幂等回执在同一事务确认。
10. **D10 — 分段与来源链。** 每段有不可变身份、范围、单调原文序号、触发原因、内容哈希及有序来源。投影指向原文身份/版本或摘要与裁剪派生记录；完整导出按原文顺序和边界生成，回查按引用定位。重复文本不是身份，不能按正文相同去重；元数据版本变化不计成新的用户发言。清空与回退记录独立边界，历史片段不重新成为当前指令。
11. **D11 — 语义版本。** 保持现有 SQL 表结构，新增分段 JSON 的独立格式版本；启用新语义版本门禁，旧程序在写业务数据前拒绝打开新会话。已保留的旧版本标识不复用。
12. **D12 — 显式旧会话升级。** 停止旧进程、确认无活 owner、备份并显式离线升级；启动不静默迁移。升级保护输入账本、工具记录、附件、等待状态及原检查点，失败不回填为空会话。升级后只保证当时实际还存在的资料。
13. **D13 — 幂等与未知结果。** 操作摘要覆盖原文段、来源引用和新投影。相同操作重试不得重复归档，内容冲突必须拒绝；提交确认丢失时通过既有回执查证，查明前不重放。
14. **D14 — 查询接口。** 提供只读归档列表、按 ID 分页读取及模型只读工具；参数有输出上限。默认只允许当前会话与当前执行范围，ID 不能变为任意文件路径或跨会话跳转。
15. **D15 — 导出。** 默认导出按来源展开的可恢复完整历史，支持显式导出当前投影。清空与回退片段带状态边界；无法恢复的旧摘要明确标识，不能让模型编造原文。
16. **D16 — 后台状态。** 归档不取代调度器、待确认工具结果或等待权威状态；恢复代码消费的控制 JSON 与未确认投递消息不裁剪。迟到事件仅由原有确认路径消费。
17. **D17 — 主子隔离。** 主执行和子执行使用各自持久化入口与范围，普通子代理不自动获得父归档访问权。fork 只携带原本可见材料所需的来源闭包，不能借回查扩大 exactTools 或信息范围。
18. **D18 — 分支与生命周期。** 新分支复制所需归档闭包和附件身份，避免清理源会话后悬空。清空、回退和最终封存都有明确归档行为；不增加默认独立归档 GC。
19. **D19 — 图片与原文边界。** 已保存的内联图片按现有消息结构保留一次，后续压缩通过来源引用复用；外部附件保留并登记路径、身份和哈希。保留调用元数据与投递标记，本批不强制将内联图改成外部文件。附件缺失按现有恢复规则处理，不能声称恢复了不存在的图像。
20. **D20 — 来源和交付。** 固定 DeepSeek Harness 参考版本并保留必要声明；先完成关键接缝独立复核，再接下游。集中交付构包并验证实际安装，不以源码通过代替安装和体验证据。

## Testing Decisions

1. **唯一主验收路径**：普通 CLI → 本地 HTTP/SSE 合成模型 → 持久化会话 → 关闭进程 → 新进程重开 → 归档读取与导出。断言实际请求、可读产物和执行次数，不断言内部私有函数的调用顺序。
2. **必要补充接缝**：原子提交、取消等待与提交确认丢失无法仅靠 CLI 稳定定位时，复用现有 StorageWorker/StoragePort 和数据库失败入口；不另建一套存储模拟器或组合故障框架。
3. **策略测试**：迁移固定来源中的预算、配对切点、近期保留、摘要重整和未缩小拒绝语义，补充 RuoCun 已确认失败停止差异。
4. **已有先例**：现有普通会话命令测试已覆盖本地服务、多进程、分支与导出；现有恢复测试已覆盖幂等、取消等待后提交和重开；后台存储测试已覆盖真实回滚与丢失确认。优先扩展这些入口。
5. **测试环境**：明确环境白名单；HOME、配置、会话、临时目录均为合成工作区。普通自动验收不调用真实模型、不读取真实用户记忆，不继承真实凭据。
6. **测试时点**：开发期按受影响来源与最小复现定向运行；归档、取消和恢复关键接缝独立复跑后供下游；最终一个固定候选集中全量、构包和仓库外安装。
7. **证据状态分离**：实现完成、自动通过、真实模型质量和用户体验分别记录；本轮编写计划不增加任何通过数。

## Out of Scope

- 移植 DeepSeek Harness 的 TypeScript、Cordis 容器或完整事件溯源框架。
- 引入向量库、语义搜索、知识图谱或新的长期记忆格式。
- 重建旧版本已经删除的原文、原始 HTTP 流、逐 token 的流式增量、模型隐藏推理。
- 跨产品 DAO 会话导入、跨重启特殊 fork 材料不足时自动降级继续。
- 后台工具或未知副作用的自动重放；跨主机分布式提交。
- 复杂历史浏览界面、跨会话全局搜索、独立归档自动淘汰策略。
- 自动升级正在使用的数据库、默认启动静默迁移、自动降级或跨版本失败自动回退。
- 新模型费用承诺、成套真实模型成绩，以及新的 OS 沙箱或终端系统能力。

## Further Notes
