# B 方案规划复核

日期：2026-11-13。仅审阅规格、计划、任务与清单，没有运行产品或修改产品实现。

root 编写规格、任务及发布票；compact_audit 编写技术计划；memory_audit 编写验收清单；harness_provenance 依据当前存储、权限和附件代码独立核查约束，并审阅最终文档的一致性。

已落实的修订：

- 内联图片按现有保存结构保留一次，外部附件登记身份与哈希，不强制把所有内联图外置。
- 分支只继承当前投影可达的归档闭包，避免把已清空或回退且不再引用的历史额外复制给新分支。
- 用户纯查询与模型 ArchiveRead 的正常工具账本分开；后者可以推进正常 checkpoint revision。
- C09 增加旧程序对新语义版本的业务写入门禁；C14 补齐清空/回退的原文回看与投影不回灌。
- 存储回滚复用一次既有确认回滚 seam，取消与丢确认沿已有用例，不建立逐 SQL 故障矩阵。
- 明确旧程序版本门禁早于 owner/epoch 业务写入；保留 SQL user_version=1 与升级 storage_version=3 的方案是设计提案，尚未迁移真实会话。

静态文档核查见 [planning-validation.json](planning-validation.json)，脚本 [validate_docs.py](validate_docs.py)只解析文档和既有测试定义，不导入产品。
