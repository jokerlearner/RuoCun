# 摘要原始前缀复用增量规格

状态：用户选择 B 后已实施、自动与独审及现用渠道真实指标通过；2026-11-13（Asia/Shanghai）。实际结果见[delivery.md](delivery.md)。

用户要求在对齐 DeepSeek Harness 摘要设计的同时取得高缓存命中，并明确允许真实 API 测试。该授权覆盖本次合成材料的有限真实模型实验，不把服务端 best-effort 缓存解释为永久命中保证。

## 行为与验收

- F1 / AC1：需要摘要时读取原始消息的连续旧前缀，保留原有 system、Hook、Todo、图片及历史顺序；候选工具裁剪不悄悄改写摘要输入。最终 wire 消息必须与同路由主请求的连续前缀结构等值。
- F2 / AC2：默认同模型摘要深拷贝本次有效连接、工具顺序/定义与 thinking/effort，末尾追加现有摘要指令。显式异模型覆盖继续尊重，并标记不保证主模型缓存复用。保留摘要输出 cap，移除主轮强制工具选择和冲突的 extra 输出 cap。
- F3 / AC3：按最终 Chat/Responses 请求体计量工具、历史、图片和真实输出上限；原始前缀放不下时明确停止，保留原投影，不静默去图/截断。
- F4 / AC4：摘要调用不接入工具分发，含工具调用的返回拒绝提交；取消、失败、截断、空摘要、未缩小、保存未确认均沿既有停止契约。用量只记一次。
- F5 / AC5：归档来源覆盖摘要实际使用的全部前缀；仍按实际被替换旧段检查缩小，不能用保留的 system 充数。原文闭包/重开回查保持。
- F6 / AC6：审计记录经脱敏的实际摘要请求维度，不能以空指纹冒充稳定或把合成 hit 当作供应商收益。
- F7 / AC7：真实 API 使用既有账号原始 endpoint，材料全部合成，配置/凭据只读，不读取真实会话，不记录认证头/密钥/原始异常。先登记规模、调用上限及预算；全部冷启动、失败、预热和暖请求均留用量记录。

## 真实验证口径

先固定合成长历史、工具与输出 cap，再执行协议探测和三次预登记摘要。主请求与摘要的共同消息前缀结构要求 100% 一致；共同前缀占摘要输入估价至少 95%。暖摘要供应商 hit/prompt 目标逐次及加权至少 90%，冷启动/预热单列但计入总调用与费用。若不达标保留所有结果并定位原因，不挑选最好一次、不无限预热。实际材料规模/账号渠道/价格/调用上限在实验 manifest 中、任何付费调用之前固定。

## 边界

不增加本地 KV 服务，不扩展成全 Agent 缓存系统，不修改真实会话与配置，不自动更新日常安装，不提交或推送现有混合工作区。全局协议仅对本次真实接入证明必要的 DeepSeek reasoning 回传做有限兼容修复；其它模型保持既有行为。
